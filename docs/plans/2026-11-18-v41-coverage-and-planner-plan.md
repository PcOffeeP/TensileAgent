## 1. 用一条轨迹定义修复

| 观察 | 现有行为 | 验收行为 |
|---|---|---|
| 40 秒视频，[0,40] 报“发生断裂” | 进入 `NARROWING`，可信边界仍为 [0,40] | 保留这条全片正证据，此时缺乏局部正证据，不能直接确认断裂 |
| [10,20] 报“未断裂” | 由于候选范围仍覆盖全片，进入 `COVERAGE` | 按 V4.1 的 later 语义将可信区间更新为 [20,40]，进入后续搜索，不启动阴性覆盖。前两条观察可以同时成立 |
| 此时耗尽预算，或规划器建议整片未断裂 | 原路径可在五个阴性窗后发布 `no_fracture` | 当前证据不足以发布整片结论；有预算可继续，实际耗尽时按现有合法拒判语义返回。另一对照轨迹若得到后续局部正证据，应仍能依现有门槛确认断裂 |
| 独立对照：初始全片报“未断裂”，五个规定窗均稳定阴性 | 1 次初始规划、6 次视觉观察后发布 `no_fracture` | 保持这条轨迹及调用次数。缺窗、错窗或缺失元数据不能补足覆盖 |

## 2. 改动模块与影响

| 模块 | 要改什么 | 影响面 |
|---|---|---|
| `agent/iterative_agent.py` 的 `_transition_v4_1` | 用当前有效观察的实际 `sample_range` 与 [0,duration] 做容差比较，复用 `_same_range`；覆盖中的固定窗继续按预期位置匹配。局部阴性进入已有 `V41EventBounds.apply` 方向更新路径 | 改变错误轨迹的下一次采样窗、视觉调用次数、事件序列和潜在最终结论 |
| 同文件的 `_has_complete_no_fracture_coverage`、`_can_terminate`、`_force_terminate` | 建立 V4.1 共用的阴性发布判定：有实际全片稳定阴性启动的本次覆盖、五个属于这轮覆盖的有效阴性窗、无尚未解释的正证据。避免从整段历史任意拼窗；若进入覆盖可重置，以覆盖开始的证据索引限定本轮。规划器请求终止和程序自动/耗尽收口均调用同一判断。保留基础设施失败优先级 | 涉及两种规划器及 CLI/Web 共用路径。V2 走原规则。正常收口发生在本轮记录写入后，需专门检查第 5 窗计数与历史落账的先后 |
| `tests/test_v4_1_coverage_scheduler.py`、`tests/test_v4_1_search_policy.py` | 在前者通过真实 `run()` 回放上表，额外覆盖旧窗混入、本次证据不全时模型请求终止、程序收口；在后者断言方向和边界。只替换外部视觉与规划回复 | 直接断言实际取样范围、覆盖进度、观察数和最终信封。旧 `test_iterative_agent.py` 的自动 fixture 替换三个证据守卫，不能作为唯一验收 |
| `agent/prompts.py`、Runner、Web、评分与交付 | 核对现有提示是否与修正规则一致；CLI/Web 回归相同结果信封和事件字段，评测区分修复前后运行版本 | 首个改动无需改变公开字段、工具签名、冻结视觉契约、训练仓或历史成绩。前端轨迹内容会随行为变化 |

**待明确的业务取舍。** 一次全片阳性后仍可能出现视觉误报。首版建议保留该观察，在缺少明确的撤销证据规则时不发布与其相抵触的整片阴性；预算结束允许拒判。这个选择可能提高拒判率。是否允许后续证据推翻早期阳性，应在真实误判样例上另行定义，不能用累计阴性票数暗中替代。

**验收顺序。** 先确认反例在旧代码上失败，分别修覆盖入口与发布出口，再运行 V4.1 调度和搜索测试、Runner/Web 及 V2 回归，最后执行 `python3 -m pytest tests -q`。同窗复查卡住、一般拒判原因和 CLI 契约优先级各有独立反例，应单独修改，避免把结果变化都归因到本次修复。

## 3. 如何决定 Agent 或工作流

建议把可重复执行的工作流作为骨架。程序负责部署与帧表验证、强制覆盖、同窗复查、边界、预算与最终发布。需要评价的策略能力只有在存在多个合法选择时，下一次应观察哪个窗口，以及是否值得继续。用户意图解析是独立能力，两组使用同一解析结果。

| 问题 | 实施办法 |
|---|---|
| 两组比较什么 | 同一修复后的 Runtime，A 接现有确定性规划器，B 接现有本地 LLM 规划器。固定视频、视觉部署与提示、初始状态、容差、预算上限和裁决；两个策略可根据各自观察走不同采样路径。比较前，确保 `agent/llm.py` 中确定性规划器能读到程序调度观察及稳定证据索引，目前它仅从工具消息重建历史 |
| 怎么控制成本 | 先用相同受控观察回放验证两者受相同证据约束，再在既有开发诊断集逐视频配对。按整片阴性、需定位、特殊或疑难场景分别统计。记录强制轮、自主轮、实际视觉/决策请求、重试和端到端耗时。历史三策略结果同时改变了扫描方式及逐轮校验，不能单独归因于规划器 |
| 什么结果支持选型 | 看断裂召回、整片误报、拒判率、时间命中及其分母，再看成本。比较前约定可接受的质量差和资源上限。确定性方案在容许差内且更省时则作为默认；LLM 收益稳定且足以抵偿成本则用于自主搜索；收益只集中于可提前识别的难例才考虑按条件启用。样本不足则保持现有默认，记录不确定性 |
