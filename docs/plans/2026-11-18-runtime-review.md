## 二、六项缺陷复核

| 编号 | 证据和适用范围 | 建议 |
|---|---|---|
| B1　FPS | Runner 写 `original_fps`，Prompt 读 `fps`。按 Runner 格式提供 25 fps，实际构造的上下文为 `FPS: 0.0`。影响决策上下文，V4.1 单调边界没有使用该值。 | 读取规范字段，兼容已有输入，未知值显示“未知”。 |
| B2　容差 | 边界对象按配置判断可发布，公开结果要求宽度不超过 1 秒。设容差 2 秒、边界 [2, 3.5]，前者通过，最终校验失败。确定性规划器另有 1 秒常量。 | 保留公开 1 秒上限，加载时校验有限数值且 `0 < tolerance_seconds ≤ 1`；规划器、运行时读取同一有效容差。 |
| B3　双写诊断 | 索引错误分支中 `_reject_indices` 内外都调用单轮收尾，覆盖同一轮诊断文件。V4.1 的 `clip_state` 分支提前返回，未经过该路径。 | 旧索引路径只收尾一次，测试断言一次写入。优先级低于当前主链路。 |
| B4　后端默认值 | 随仓配置选 local；Runner、决策工厂、意图入口的缺省值仍有 remote。显式配置缺键时可能选远程，是否发出请求取决于地址及凭据。意图解析还先于任务配置、CLI 覆盖和 Web 快照单独加载配置。 | 先解析任务有效配置，再传给意图与规划。缺省统一 local，显式远程才允许用远程。保留意图模型故障时的规则兜底。 |
| B5　温度 | 已配置的常规路径使用 0.2；运行时和客户端方法缺省仍有 0.7。对忽略温度的确定性策略无直接影响。 | 配置归一时统一默认 0.2，显式值优先。 |
| B6　错误降级 | 最终聚合调用 `FinalOutput` 时广泛捕获异常，并改为 `unrecognized/invalid_model_output`。B2 的最小复核实际触发该降级。 | 视觉响应解析错误保留轮级原因；程序生成的最终结果违反契约时，沿 Runner 的 `ok=false` 返回内部错误。CLI、Web 与事件需呈现一致。 |

主要实现入口为 [运行循环与终止](../../agent/iterative_agent.py)、[公开结果契约](../../agent/schema.py)、[任务配置与结果信封](../../agent/runner.py)、[意图解析](../../agent/interaction.py)、[每轮上下文](../../agent/prompts.py) 和 [规划器](../../agent/llm.py)。

## 三、本次实测与原报告遗漏

- **零次视觉调用即可结束。** 在 V4.1 的正常 `IterativeAgent.run()` 循环注入首轮规划建议 `terminate(unrecognized, max_rounds)`，预算设为 10。实测返回 `unrecognized/max_rounds`，视觉调用 0 次、证据 0 条。该测试证明路径可达；真实模型触发频率尚未测量。`_can_terminate` 对特殊样例有同窗复核，但对多个一般拒判原因只检查枚举。优先把“预算耗尽、冲突、非法输出”等原因绑定到程序观察到的事实。
- **跨仓交付校验失败。** 本仓 bundle 自检通过；加上 `--mvllm-root ../mVllm_2` 后仅报 `canonical model component hash mismatch`。两份模型清单的文本差异是 `artifact.managed_remote_path` 的前缀由 `workspace/models/` 变为 `models/`。两边声明的模型聚合哈希相同，本次未重算权重。相邻仓提交 `cf66874` 记录目录布局调整。
- **当前测试基线。** 使用项目 Python 3.11 虚拟环境，继承本机代理时 550 通过、4 失败，四项均在 HTTP 客户端初始化时因缺少 SOCKS 可选依赖而失败；仅在测试进程去除代理并使用独立临时目录后，554 项全过。Web 的 `npm run build` 通过。复核未调用远程 GPU，也未执行新质量验收。
- **召回值得优先跟踪。** 当前交付卡的历史 110 条中，断裂召回 31.11%，未断裂召回 85.00%。该快照无法拆解规划器和视觉模型各自的影响；其中部分字段因历史评分器未识别标注列名而缺测。实验前要验证评分字段覆盖率。[中间交付卡](../../delivery/current/PRODUCT_CARD.md)

## 四、建议执行顺序与验收

| 批次 | 实施边界 | 完成标准 |
|---|---|---|
| P0　恢复可信基线 | 运行时先补拒判原因的事实条件、B2/B6、任务级配置隔离；B1/B5 随相应模块小改。交付问题作为独立改动，先核实当前清单路径指向预期发布物，再以权威清单按现有流程生成新交付记录，保留历史及验证范围。 | 首轮虚报耗尽被拒，真实预算耗尽和有依据的特殊样例仍可收口；非法配置在模型调用前失败；最终契约错误返回失败信封；CLI 配置和 Web 快照在意图与决策阶段一致。两仓校验通过，清单相等、真实服务验证各自记录。 |
| P1　比较两种规划器 | 同一 V4.1 Runtime 分别接现有确定性规划器与当前本地 LLM；固定同一意图输入或已解析意图、视频、视觉部署、提示版本、容差、证据门槛和预算上限。沿用现有数据划分、身份核验与评分逻辑，为新对照单独记录协议。 | 开发诊断集先检查标签映射、逐轮证据编号与请求计数。确定性规划器当前从工具消息重建历史，程序调度轮可能只在用户上下文出现，需验证两策略可见的证据相同。正式比较前锁定评分与选择规则。 |
| P2　按已验证行为拆分 | 优先从运行循环抽出终止判断和单轮证据记录，复用 `V41EventBounds`。用 CLI/Web 公开结果、错误信封、事件、历史引用的前后对照覆盖关键轨迹。B3、只写计数器与旧测试分别小批处理。 | 相同输入轨迹产生相同的合法结论，预期变更逐项列明；覆盖局部正例、完整阴性、冲突、同窗复查、预算耗尽与基础设施失败。Python 回归通过，涉及 Web 时构建通过。 |

**策略选择规则。** 主指标用断裂召回，同时报告阴性误报、拒判率、时间窗命中及可评分样本数。逐视频配对统计实际视觉调用、决策调用和端到端耗时；相同上限允许策略提前结束，执行失败单列并保留在样本账本。优先复用现有 diagnostic30 排查差异，冻结后在事先锁定的数据上确认，披露与既往调参样本的重叠及小样本不确定性。原冻结实验的单次/固定扫描结果可作旁证。若确定性规划在预先约定的质量容忍范围内且成本更低，再将其设为默认；若 LLM 有稳定收益，保留 LLM 默认；样本不足以区分时保留当前默认并报告差异。三种结果均独立保留意图识别的产品决策。
